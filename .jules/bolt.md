## 2024-08-02 - Canvas Optimization

**Learning:** Re-assigning canvas dimensions (`canvas.width = canvas.width`) forces the browser to re-allocate the underlying graphics buffer and clear the canvas, which is an expensive operation that can cause layout thrashing. This is a common performance bottleneck in canvas-heavy React components like `PreviewCanvas.tsx` when re-rendering based on user interaction (like mouse moves or drawing annotations).
**Action:** When updating canvas dimensions within a `useCallback` or `useEffect` render pipeline, conditionally set them only if they have actually changed (`if (canvas.width !== targetW) canvas.width = targetW`). Since avoiding dimension re-assignment stops the implicit clear, explicitly call `clearRect` when the dimensions remain the same to prevent visual ghosting/artifacts.

## 2024-08-07 - Canvas `getImageData` Optimization
**Learning:** Calling `ctx.getImageData()` synchronously reads back pixels from the GPU to the CPU, stalling the rendering pipeline and causing severe performance bottlenecks, especially inside a busy render loop (e.g., drawing blur annotations). Creating new transient `<canvas>` elements (`document.createElement('canvas')`) on every render frame causes massive garbage collection (GC) thrashing and layout overhead.
**Action:** Replace `ctx.getImageData()` with `ctx.drawImage(ctx.canvas, ...)` onto an off-screen canvas whenever possible, keeping pixel operations on the GPU. Always cache off-screen canvases at the module level rather than creating them inside render functions to eliminate GC pressure. When reusing a canvas, conditionally assign `.width` and `.height` to avoid the implicit and expensive clearing overhead if dimensions haven't changed.
